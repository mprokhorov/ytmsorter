# YTM Sorter

PWA для просмотра и сортировки двух плейлистов YouTube Music — «Треки» и «Музыка». Работает только через официальный YouTube Data API v3, напрямую из браузера, без собственного бэкенда.

- **Трек** — автосгенерированный музыкальный трек с обложкой альбома (Art Track): канал `… - Topic` и/или описание `Provided to YouTube by … Auto-generated by YouTube`.
- **Музыка** — любое другое видео: клипы, лайвы, пользовательские видео.

## Возможности

- Вход через Google (Google Identity Services, token client, scope `https://www.googleapis.com/auth/youtube`). Без собственного сервера Google выдаёт только токен на час, а новый можно получить лишь через окно Google в ответ на касание. Поэтому приложение продлевает сессию само на первом касании экрана — когда токен истёк или до конца осталось меньше 10 минут; окно Google на мгновение мелькает и закрывается. Если окно не закрылось само (например, Google попросил выбрать аккаунт), автоматические попытки делают паузу на минуту, а в баннере остаётся кнопка «Продлить сессию». Состояние при этом не теряется.
- Выбор плейлистов «Треки» и «Музыка» из списка ваших плейлистов. Выбор хранится в `localStorage`.
- Синхронизация только ручная: по кнопке «Обновить». Между запусками показываются последние загруженные данные. Автоматически загружается лишь плейлист, который ещё ни разу не загружался (например, сразу после выбора в настройках). Перед построением плана сортировки или переноса нужные плейлисты загружаются заново, чтобы план не строился по устаревшим данным.
- Сортировка по правилам исходного Python-скрипта:
  - «Музыка» — по названию;
  - «Треки» — по первому исполнителю, альбому и названию.
- Перед сортировкой показывается план (dry-run): число ходов, стоимость в квоте, какие элементы куда переезжают. Запись начинается только после подтверждения.
- Минимальное число ходов: `n − LIS`. Каждый ход — это `playlistItems.update` с `snippet.position`, ходы выполняются строго последовательно.
- Прогресс-бар, кнопка остановки, продолжение после `quotaExceeded` или обрыва. При продолжении плейлист загружается заново, а план пересчитывается.
- Локальный учёт квоты за сутки со сбросом в полночь по тихоокеанскому времени.
- Подсветка элементов, попавших не в свой плейлист, и их перенос: `insert` сразу на правильную позицию, затем `delete` — 100 единиц за элемент.
- Архив. Всё, что приложение видело в плейлистах, запоминается. Если видео становится недоступным (удалено или стало приватным), оно попадает в архив с последними известными названием, исполнителем, альбомом и обложкой. Записи можно добавлять и редактировать вручную, архив можно экспортировать и импортировать в JSON. Хранится только в этом браузере — делайте экспорт.
- Защита от случайной записи: для каждого плейлиста есть флажок «Разрешить запись», по умолчанию выключен. Пока он выключен, приложение только читает плейлист и показывает планы. Проверка выполняется в коде вызова API, а не только в интерфейсе.

## Правила сортировки

Эталон — исходный скрипт:

```python
def sort_music_key(track):
    return track.name.lower(), str(not track.name[-1].isupper())

def sort_tracks_key(track):
    return (track.artist.lower(), str(not track.artist[-1].isupper()),
            track.album.lower(), str(not track.album[-1].isupper()),
            track.name.lower(), str(not track.name[-1].isupper()))
```

`track.artist` — первый исполнитель. Остальные исполнители показываются в списке, но в сортировке не участвуют, как и в скрипте.

Реализация в `src/domain/pystr.ts` и `src/domain/keys.ts` воспроизводит его в точности:

- Строки сравниваются по кодовым точкам Unicode, как в Python, а не по UTF-16 и не через `localeCompare`.
- Флаг — строка `"False"`/`"True"`. При равенстве строк в нижнем регистре раньше идёт та, что оканчивается заглавной буквой.
- `isupper()` проверяет последнюю кодовую точку, суррогатные пары учитываются. Для не-букв результат `False`, значит флаг `"True"`.
- Пустая строка не роняет сортировку: флаг `"True"`.
- Сортировка стабильная, как в Python. Недоступные видео ставятся в конец в текущем порядке.

`tests/keys.test.ts` сверяет результат с фикстурой, которую сгенерировал настоящий Python (`tests/fixtures/gen_sort_fixture.py`) на случайных данных: кириллица, регистр, цифры, символы, астральные символы; отдельно — 600 треков с одним–тремя исполнителями, где учитывается только первый.

Исполнитель и альбом трека берутся из описания автотрека:

```
Provided to YouTube by …

Название · Исполнитель1 · Исполнитель2

Альбом
…
```

Исполнители — все после названия, в исходном порядке (так они и показываются). Альбом — следующая непустая строка. Если строку с `·` найти не удалось, исполнителем становится имя канала без ` - Topic`.

## Настройка Google Cloud

### 1. Проект

1. Откройте <https://console.cloud.google.com/>.
2. В выпадающем списке проектов вверху нажмите **New project**. Задайте имя, например `ytm-sorter`, и нажмите **Create**.
3. Убедитесь, что новый проект выбран в списке вверху.

### 2. YouTube Data API v3

1. **APIs & Services → Library**.
2. Найдите **YouTube Data API v3** и нажмите **Enable**.

### 3. OAuth consent screen

1. Перейдите в **APIs & Services → OAuth consent screen**. В новой консоли раздел называется **Google Auth Platform**, там есть вкладки **Branding**, **Audience**, **Data Access**.
2. Нажмите **Get started**. Укажите название приложения (`YTM Sorter`) и свой email для поддержки.
3. **Audience: External**.
4. Контактный email разработчика — свой. Примите условия и нажмите **Create**.
5. Откройте вкладку **Audience**:
   - статус публикации должен быть **Testing**, в прод публиковать не нужно;
   - в **Test users** нажмите **Add users** и добавьте свой Google-аккаунт, в котором лежат плейлисты.
6. На вкладке **Data Access** можно добавить scope `https://www.googleapis.com/auth/youtube`. Это необязательно: приложение запрашивает его само.

В режиме Testing при входе Google покажет предупреждение «Google hasn't verified this app». Нажмите **Continue**: приложение ваше, а вы — его тестовый пользователь.

### 4. Web OAuth client

1. **APIs & Services → Credentials → Create credentials → OAuth client ID**. В новой консоли: **Google Auth Platform → Clients → Create client**.
2. **Application type: Web application**.
3. **Authorized JavaScript origins**. Указывается только origin, без пути:
   - `http://localhost:5173` — для `npm run dev`;
   - `http://localhost:4173` — для `npm run preview`;
   - `http://localhost` — рекомендация Google для локальной разработки;
   - `https://<ваш-логин>.github.io` — для GitHub Pages, например `https://mprokhorov.github.io`.
4. **Authorized redirect URIs** оставьте пустым: token client их не использует.
5. Нажмите **Create** и скопируйте **Client ID** вида `1234567890-abc….apps.googleusercontent.com`. Client secret не нужен и никуда не вписывается.

Изменения origins иногда применяются через несколько минут.

## Куда вписать Client ID

Client ID не секрет: он всё равно виден в коде страницы. Но в репозиторий он не коммитится, а подставляется при сборке из переменной `VITE_GOOGLE_CLIENT_ID`.

- **Локально:** создайте файл `.env.local` по образцу `.env.example`:

  ```
  VITE_GOOGLE_CLIENT_ID=1234567890-abc….apps.googleusercontent.com
  ```

- **GitHub Pages:** **Settings → Secrets and variables → Actions → вкладка Variables → New repository variable**:
  - Name: `VITE_GOOGLE_CLIENT_ID`
  - Value: ваш Client ID

Если собрать приложение без Client ID, оно покажет экран с подсказкой.

## Локальный запуск

Нужен Node.js 22+.

```bash
npm install
cp .env.example .env.local   # и вписать свой Client ID
npm run dev                  # http://localhost:5173
```

Остальные команды:

```bash
npm test            # юнит-тесты (Vitest)
npm run typecheck   # проверка типов
npm run build       # production-сборка в dist/
npm run preview     # локальный просмотр сборки, http://localhost:4173
```

Service worker работает только в production-сборке (`build` + `preview`, или GitHub Pages).

## Деплой на GitHub Pages

1. **Settings → Pages → Build and deployment → Source: GitHub Actions**.
2. Добавьте переменную `VITE_GOOGLE_CLIENT_ID`, как описано выше.
3. Добавьте `https://<логин>.github.io` в Authorized JavaScript origins OAuth-клиента.
4. Сделайте push в `main` или запустите workflow **Deploy to GitHub Pages** вручную (**Actions → Deploy to GitHub Pages → Run workflow**).
5. Приложение откроется по адресу `https://<логин>.github.io/<имя-репозитория>/`.

Workflow `.github/workflows/deploy.yml` устанавливает зависимости, прогоняет тесты, собирает проект с `base = /<имя-репозитория>/` и публикует `dist/`. Для остальных веток и pull request'ов `ci.yml` запускает проверку типов, тесты и сборку.

## Первая проверка записи

Никакой записи в настоящие плейлисты, пока вы явно не включите «Разрешить запись». Рекомендуемый порядок:

1. Создайте в YouTube Music тестовый плейлист, например `YTMS Test`, и добавьте в него 15–20 элементов вперемешку: треки и клипы, пару одинаковых названий в разном регистре, кириллицу. Порядок сортировки плейлиста должен быть **«Вручную»**.
2. В настройках приложения временно выберите его как «Треки», включите запись только для него и выполните сортировку.
3. Проверьте результат в YouTube Music. Повторный план должен показать «Плейлист уже отсортирован».
4. Верните настоящий плейлист и посмотрите dry-run. Если он был отсортирован старым скриптом, ходов должно быть около нуля. Большое число ходов означает, что исполнитель или альбом из описания разошлись с данными ytmusicapi. Их видно в плане — сообщите, поправим парсинг.
5. Только после этого включайте запись для настоящих плейлистов.

## Квота

| Операция | Стоимость |
|---|---|
| `playlists.list`, `playlistItems.list` (страница из 50) | 1 |
| `playlistItems.update` (один ход сортировки) | 50 |
| `playlistItems.insert` / `delete` | 50 |

Дневной лимит — 10 000 единиц, то есть около 200 ходов в сутки. Если плану не хватает квоты, выполнение остановится на `quotaExceeded`, а после полуночи по тихоокеанскому времени его можно продолжить. Счётчик в шапке приложения — локальная оценка по запросам этого браузера. Точные цифры — в Google Cloud Console → **APIs & Services → YouTube Data API v3 → Quotas**.

Позиции (`snippet.position`) работают только у плейлистов с ручным порядком. Если API вернёт `manualSortRequired`, приложение предложит переключить сортировку плейлиста на «Вручную».

## Структура

```
src/
  auth/token.ts        Google Identity Services, продление токена
  api/client.ts        fetch-обёртка, ошибки API, учёт квоты
  api/youtube.ts       playlists / playlistItems, защита записи
  domain/pystr.ts      сравнение строк как в Python
  domain/keys.ts       ключи сортировки
  domain/classify.ts   трек или музыка
  domain/parse.ts      разбор описания автотрека
  domain/item.ts       ответ API → модель элемента
  domain/order.ts      целевой порядок
  domain/plan.ts       LIS и план перемещений
  domain/transfer.ts   перенос между плейлистами
  domain/thumbs.ts     выбор и обрезка обложек
  state/…              настройки, квота, плейлисты, архив, выполнение операций
  ui/…                 компоненты интерфейса (Preact)
tests/                 юнит-тесты
```

Стек: Vite, TypeScript, Preact + Signals, vite-plugin-pwa, Vitest.
