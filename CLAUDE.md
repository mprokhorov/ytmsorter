# YTM Sorter — заметки для работы над проектом

PWA для сортировки двух плейлистов YouTube Music («Треки» и «Музыка») через YouTube Data API v3. Vite + TypeScript + Preact/Signals, без бэкенда. Подробности для человека — в README.

## Как работаем

- Коммиты идут прямо в `main`. Push в `main` = автодеплой на GitHub Pages (`.github/workflows/deploy.yml`). После push проверить, что деплой зелёный, и назвать пользователю версию: она видна внизу настроек («Версия <sha>»). Новая версия ставится, когда приложение свёрнуто, поэтому увидеть её можно после сворачивания и повторного открытия.
- Перед push: `npm run typecheck`, `npm test`, `npm run build`, плюс проверка в браузере (Playwright + Chromium из `/opt/pw-browsers`) на макете API.
- Код без комментариев. Интерфейс на русском. Стиль — как в окружающем коде.
- Фразы интерфейса (подсказки, плашки, ошибки, тосты) — без точки в конце последнего предложения; внутри фразы точки между предложениями остаются. Сокращений вроде «шт.», «ед.» в конце избегать. Если сообщение собирается из частей (ошибка API + пояснение), склеивать через `sentences()` из `ui/format.ts`.
- Никаких записей в настоящие плейлисты без явного разрешения пользователя. Запись закрыта флажком «Разрешить запись» (проверка в `api/youtube.ts`).
- Основное устройство пользователя — iPhone, приложение установлено как PWA. Всё, что касается вёрстки, жестов, хранилища и жизненного цикла, проверять мыслью «как это поведёт себя в iOS Safari standalone».

## Как устроены реальные данные

Решения принимать исходя из этого, а не из того, как выглядит тестовый макет.

- **Обложка принадлежит альбому, а не треку.** Все треки одного альбома имеют одинаковую обложку. После сортировки треки одного альбома идут подряд. Любое «первые N обложек / превью / уникальные картинки» выбирать по альбомам (`domain/mosaic.ts`), а не по трекам.
- Сборники: у треков одного альбома бывают разные исполнители. Разные альбомы могут называться одинаково («Greatest Hits»).
- Альбом может не распознаться (пустая строка). Такие треки не склеивать между собой.
- Одно и то же видео может лежать в плейлисте дважды. Идентичность элемента плейлиста — `playlistItem.id`, видео — `videoId`.
- Недоступные видео («Deleted video», «Private video») остаются в плейлисте и занимают позиции.
- «Не свои» элементы: в «Треках» бывает клип, в «Музыке» — автотрек.
- Размер: плейлист YouTube — до 5000 элементов. Проверять производительность и хранилище на 5000, а не на 30 или 1000.
- **У трека может быть несколько исполнителей** (строка описания `Название · Исп1 · Исп2 …`). Храним все (`Item.artists`), показываем все в исходном порядке. Сортировка «Треков» — строго как в исходном скрипте пользователя: первый исполнитель → альбом → название; остальные исполнители в сортировке не участвуют (эталон на Python в `tests/fixtures/gen_sort_fixture.py`).
- **Исполнитель и альбом берутся из описания видео, а скрипт пользователя брал их из ytmusicapi (внутренние данные YouTube Music).** Чтобы совпадать: главный исполнитель — владелец канала (`X - Topic`), если он есть среди исполнителей, иначе первый в описании; все строки нормализуются в NFC (одна буква бывает записана разными кодовыми точками). Альбом в YouTube Music иногда отличается от описания, а через Data API его не получить — такие единичные расхождения неустранимы. Разбор реального плейлиста (455 треков): 7 расхождений → 4 после этих правок, все из-за альбома.
- Регистр и Unicode: кириллица, «ё», заглавные на конце, эмодзи и символы вне BMP, пустые строки.
- Миниатюры Art Track: 16:9 с квадратной обложкой по центру; варианты 4:3 (`high`, `standard`) — с чёрными полосами сверху и снизу.

## Чек-лист перед тем, как считать фичу готовой

1. Что здесь на самом деле уникально или является единицей: трек, альбом, видео, элемент плейлиста? Не подменяю ли я одно другим?
2. Покрывают ли тестовые данные реальную структуру: несколько треков из одного альбома, дубликаты, недоступные, «не свои», пустые поля, 5000 элементов?
3. Если тестовые данные получились «удобнее» реальных (у каждого трека своя обложка, все строки уникальны, всё помещается в память), то тест ничего не доказывает. Сначала сделать данные честными.
4. Что будет при отказе: нет сети, 401, `quotaExceeded`, переполнено хранилище, iOS выгрузила приложение в фоне?
5. Не глотаются ли ошибки молча там, где пользователь может потерять данные?

## Вход и сессия

- Бэкенда нет, поэтому есть только access token на час (GIS token client), refresh token недоступен. Новый токен — только через окно Google, а iOS открывает его лишь в ответ на касание.
- Продление — по явному окну «Сессия истекла» с одной кнопкой (`SessionExpired` в `ui/Screens.tsx`, на общем компоненте `Popup` из `ui/Popup.tsx`), поверх всех окон. Истечение отслеживается таймером и при возврате в приложение (`installExpiryWatch` в `auth/token.ts`). Неявных окон Google по касаниям и кнопкам нет — пользователь попросил явный поп-ап. Мелькание окна Google пользователя устраивает; полностью тихое продление возможно только с маленьким сервером для refresh token.

## Хранилище

- При изменении формы данных в кэше менять ключ кэша (`ytms.cache.v2` и т. д.), иначе первый запуск после деплоя прочитает старую форму.

- `localStorage` — примерно 5 млн символов на сайт.
- Приоритет данных: архив и «виденные» (`ytms.archive`, `ytms.seen`) — невосполнимые. Кэш плейлистов (`ytms.cache`, `ytms.myPlaylists`) — восполнимый.
- Невосполнимое пишется только через `saveCritical`: при нехватке места он выбрасывает кэш, повторяет запись, а если и это не помогло — показывает баннер.
- `sessionStorage` в iOS PWA очищается, когда система выгружает приложение в фоне. Всё, что должно пережить сворачивание, хранить в `localStorage`.

## Уроки (что уже пошло не так и почему)

- **Мозаика из 4 первых треков вместо 4 альбомов.** Решение принималось по картинке «4 квадрата как в YTM», а проверялось на макете, где у каждого трека была своя обложка. Урок: сначала сформулировать, какая сущность уникальна, и сделать тестовые данные с реальной структурой.
- **Молчаливое переполнение `localStorage`.** Проверялось на 1000 элементах, а при 5000 кэш почти заполнял лимит, и `save()` глотал ошибку, в том числе при записи архива. Урок: проверять на реальных максимумах и не глотать ошибки записи невосполнимых данных.
- **Отрисовка 5000 строк целиком.** Там же: на малом объёме было незаметно. Список рендерится порциями (`ui/progressive.ts`).
- **Разлогин при сворачивании на iOS.** Токен лежал в `sessionStorage`.
- **Шапка под статус-баром на iOS.** `env(safe-area-inset-top)` в режиме `black-translucent` на устройстве пользователя не сработал. Статус-бар сделан непрозрачным (`black`); после смены этого мета-тега PWA нужно переустановить.
- **Под открытым окном прокручивалась страница.** Модальные окна не должны прокручивать фон: на десктопе он блокируется, на телефоне скрывается (окно становится страницей). Проверять жестами пальца (touch-события), а не только колесом мыши.
- **Разный размер шрифта в строках с бегущей строкой на iOS.** Автоувеличение текста в Safari (text autosizing) раздувало длинные строки в одну линию. Отключено через `-webkit-text-size-adjust: 100%` на `html`; в Chromium это не воспроизводится, проверять только на устройстве.
- **Нажатие на шапку для прокрутки вверх не срабатывало на iPhone.** На iOS касание во время инерционной прокрутки только останавливает её и не порождает `click`. Такие «тапы» ловить через `pointerdown`/`pointerup` с порогом сдвига (`tapHandlers` в `ui/ui.ts`), а не через `onClick`.
- **Правило сортировки «улучшалось» и разошлось со скриптом.** Добавление остальных исполнителей в ключ переставило треки в плейлисте, уже отсортированном скриптом. Эталон — исходный скрипт пользователя; отходить от него только по явной просьбе и проверять на плейлисте, отсортированном скриптом (план должен быть пустым).
- **Прокрутка к началу не работала в окне плана на iPhone.** Пользователь нажимает на системную строку с часами, а этот жест iOS прокручивает только основную прокрутку документа, не внутренние области. Первая гипотеза (инерция) была неверной — сначала уточнять, какой именно жест имеется в виду. Решение: на телефоне окна открываются как страница, прокручиваемая документом (`html.sheet-open`, `lockPageScroll` в `ui/Dialog.tsx`), а фоновый список скрывается и затем возвращается на прежнюю позицию. Любая длинная прокручиваемая область на телефоне должна быть прокруткой документа.
- **Тактильный отклик на iOS.** Vibration API в Safari нет. Программное «нажатие» скрытого `<input switch>` на iOS 27 отклика не даёт; работает только настоящее касание системного переключателя. Поэтому в кнопки вкладывается невидимый `input[switch]` во всю площадь (`ui/haptics.ts`, класс `haptic-switch`), а флажки — сами системные переключатели. Проверено пользователем на устройстве; в Chromium отклика нет, проверять только на iPhone.
- **Зум при фокусе на поле ввода на iPhone.** Safari увеличивает страницу, если у `input`/`select`/`textarea` шрифт меньше 16px. У полей ввода всегда не меньше 16px; `user-scalable=no` не использовать.
- **Вкладки пропадали во время View Transition в Safari.** Подложку растягивала тень в 100vmax, и снимок элемента выходил огромным. У элементов с `view-transition-name` не должно быть большого ink overflow.
- **Переключение прокрученной вкладки «моргало».** View Transition снимает снимок всего экрана, а вместе с вкладкой менялась и прокрутка: содержимое на миг пропадало, новая вкладка рисовалась с нуля, обложки проявлялись заново, а строки ниже отрисованной порции «доезжали» после анимации. Теперь View Transition не используется: `setTab` в `ui/ui.ts` сам анимирует `.content` (уход 120 мс → подмена и восстановление прокрутки, пока невидимо → въезд 260 мс), `useProgressive` сразу рисует строки до восстанавливаемой позиции (`pendingScroll`), а уже показанные обложки появляются без повторного проявления (`shown` в `Cover.tsx`). Перед въездом ждём декодирования видимых картинок (не дольше 150 мс): iOS выгружает декодированные картинки скрытых элементов, и без этого обложка «вспыхивала» посреди анимации. Инерцию прокрутки при нажатии останавливаем `scrollTo` на текущую позицию — не `overflow: hidden` на `html`, от него на миг «отклеивается» закреплённая шапка. Подсветка вкладки (`selectedTab`) меняется сразу при нажатии; каждое нажатие отменяет незавершённое предыдущее (счётчик `generation`). Проверять переключение после прокрутки, замедляя анимации (CDP `Animation.setPlaybackRate`).
- **Новый класс сломал старые плашки.** Окну сессии дали класс `alert`, а он уже был у плашек (`alert--lock`, `alert--warn` …) — они сжались и выровнялись по центру. Перед новым CSS-классом искать его в `src` (`grep -rn "имя"`), и после изменения стилей смотреть на соседние экраны, а не только на новый.
- **Нажатие «Сортировать» иногда «не срабатывало».** Сервис-воркер стоял в режиме `autoUpdate`: после деплоя приложение при запуске за пару секунд скачивало новую версию и перезагружало страницу, в том числе посреди действия пользователя (и могло прервать сортировку). Теперь режим `prompt`, и новая версия ставится, только когда приложение свёрнуто и простаивает: ничего не загружается, не выполняется и не открыто окно (`src/update.ts`). Пользователь видит новую версию при следующем открытии.
- **Подсветка треков, недоступных в регионе, убрана.** Проверка `videos.list` → `regionRestriction` давала ложные срабатывания: YouTube Music сам подменяет закрытое в стране видео доступной версией того же трека, а Data API этого не показывает. Пользователь решил убрать регион и подсветку. Не возвращать без способа узнать о замене.
- **Старая иконка оставалась в истории браузера.** Браузеры кэшируют иконки по адресу файла. При смене иконки давать файлам новые имена (сейчас `public/icon-6*`; при следующей смене — `icon-7*`), а не перезаписывать старые. На домашнем экране iOS иконка и название меняются только после переустановки PWA.
- **Иконка на домашнем экране — тёмная плитка, как у YouTube Music.** Красный круг с еле заметным градиентом сверху вниз (`#fc0033` → `#d6012d`, сняты с иконки YTM) на 78% плитки, вырезанные кольцо и полоски, плитка `#232323` → `#161616` (`icon-6-touch-180.png`, `icon-6-maskable-512.png`). Прозрачность для apple-touch-icon не использовать: iOS заливает её по-своему. Отдельную светлую/тёмную иконку для домашнего экрана веб-приложение задать не может. Логотип в приложении и в браузере — тот же круг с градиентом и прозрачными вырезами (`icon-6.svg`).
- **Liquid Glass пробовали и откатили.** Стеклянный слой (`src/glass.css`, коммит `574ec52`) пользователь решил убрать и вернуться к дизайну в стиле YouTube Music. Без явной просьбы не возвращать. Если вернёмся: Chromium в контейнере без GPU не рисует `backdrop-filter` с размытием больше ~14px, на скриншотах проверять, что текст под шапкой действительно размыт.
- **Короткие сообщения — всплывающим окном, а не окном-страницей.** Если план пуст («Уже отсортировано»), показывается `Popup` по центру (`ui/Popup.tsx`: значок, заголовок, текст, одна кнопка; Escape и касание фона закрывают), а не `Dialog`, который на телефоне становится целой страницей. `Dialog` — для длинного содержимого.
